## 10. Duplicate request (idempotent replay)

Resubmitting example 1 with the same `Idempotency-Key: ex-1` returns the stored result (HTTP 200, header `Idempotent-Replay: true`) without re-running the workflow or calling the bureau.

```json
{
  "replayed": true,
  "request_id": "req_b322b722a8e64282bbf8fe848345b53d",
  "decision": "APPROVED",
  "workflow_version": 1
}
```

Same key with a *different* payload returns **409 idempotency_conflict**.
